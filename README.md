## 🧠 What Is MockMate

> **MockMate is not another generic interview prep tool.**

It's an AI interview coach built from the ground up for Indian engineering students facing campus placements. Every design decision — the pricing, the question bank, the voice mode, the social features — is built for one specific context: a CSE student in Gujarat who has 3 weeks before TCS NextStep opens.

MockMate gives you:

- 🤖 **AI-generated questions** matched to the exact company you're interviewing for
- 🎤 **Voice answer mode** so you practice speaking, not just typing
- 🔁 **AI follow-up questions** that probe your actual answer like a real interviewer would
- 🏆 **College leaderboards** to stay accountable with peers

## 🤖 Gemini AI Workflow

> MockMate treats Gemini as a structured data API, not a chatbot.

Every call to Gemini sends a carefully engineered prompt and expects back a **strict JSON object**. No prose. No markdown. Just parseable data the frontend can render directly.

```
PROMPT DESIGN PHILOSOPHY
─────────────────────────────────────────────────────────────────

1. SYSTEM CONTEXT
   Role: "You are a senior technical interviewer at a top Indian
          product company. Your job is to evaluate a candidate's
          answer and return structured JSON feedback."

2. STRUCTURED OUTPUT REQUIREMENT
   "Respond ONLY with valid JSON. No explanation, no markdown,
    no extra text. Invalid JSON = unusable response."

3. DOMAIN INJECTION
   • Company name (TCS / Zoho / FAANG)
   • Topic area (DSA / OOP / DBMS / OS / System Design / HR)
   • Difficulty level (Fresher / 1-year exp / Senior)

4. CONTEXT WINDOW
   • Previous questions in this session
   • Candidate's answer to the current question
   • For follow-up: the answer text itself

5. EXPECTED RESPONSE SCHEMA
   {
     "score": 7,              // out of 10
     "feedback": "string",    // 2-3 sentences
     "strengths": ["..."],    // what was good
     "improvements": ["..."], // specific gaps
     "followUpQuestion": "string",   // 1 targeted follow-up
     "weakAreas": ["DSA", "Time Complexity"]  // for pattern detector
   }

6. FALLBACK HANDLING (CRITICAL)
   try {
     const parsed = JSON.parse(geminiResponse);
   } catch {
     // Claude occasionally returns malformed JSON
     // Fallback: show generic feedback, log for review
   }
```

**Why this approach is better than free-form AI output:**
- Frontend renders data, not text → consistent UI
- Scores are comparable across sessions → leaderboard works
- Weak areas are extracted programmatically → pattern detector works
- Response size is predictable → faster latency

## 📡 REST API Reference

### 🔐 Auth Routes

```
POST   /api/auth/register
       Body:   { name, email, password, college, targetRole }
       Returns: { accessToken, user }

POST   /api/auth/login
       Body:   { email, password }
       Returns: { accessToken, user }
       Cookie:  refreshToken (httpOnly, 7d)

GET    /api/auth/google
       Redirects to Google OAuth consent screen

GET    /api/auth/google/callback
       Handles OAuth redirect, issues JWT pair

POST   /api/auth/refresh
       Cookie:  refreshToken
       Returns: { accessToken } (new 15-min token)

POST   /api/auth/logout

## 💡 Engineering Decisions

> *Every decision here was a choice — not a default.*

<details>
<summary>🔐 Why JWT + Refresh Tokens (not sessions)?</summary>

Stateless authentication that works across separate Vercel (frontend) and Render (backend) deployments. Short-lived access tokens (15 min) limit exposure if intercepted. Long-lived refresh tokens (7 days, httpOnly cookie, not accessible to JS) handle silent re-auth without repeated logins. This exact pattern is used by production apps like Notion and Linear.

</details>

<details>
<summary>🏛️ Why MVC architecture?</summary>

Separation of concerns — routes only define endpoints, controllers hold business logic, models handle schema/validation, services abstract external APIs. This means swapping Gemini for Claude or OpenAI requires changing exactly one file (`gemini.service.js`), not hunting through controllers. Scales to a team; readable by a recruiter in 30 seconds.

</details>

<details>
<summary>🍃 Why MongoDB over PostgreSQL?</summary>

Interview sessions are deeply nested documents — each session contains an array of questions, each question contains an answer, AI feedback, follow-up, and voice transcript. Storing this in SQL requires 4+ joins per session read. MongoDB stores the whole session as one document — single read, single write, trivially scalable. The schema flexibility also let me iterate the question/feedback shape without migrations.

</details>

<details>
<summary>🤖 Why Gemini AI over ChatGPT?</summary>

Three reasons: (1) Gemini Flash has a generous free tier — critical for a bootstrapped student project. (2) Gemini consistently returns valid JSON when prompted correctly, which is the core requirement for structured feedback. (3) The Gemini SDK's Node.js client is actively maintained. The service layer means switching to another provider later is a one-file change.

</details>

<details>
<summary>🔧 Why a dedicated AI Service Layer?</summary>

`gemini.service.js` is the only file that imports the Gemini SDK. If Gemini goes down, raises prices, or a better model ships — swap one file. Controllers don't know or care which AI they're calling. This is dependency inversion applied to external APIs, and it's the reason production codebases at scale use service layers.

</details>

<details>
<summary>💳 Why Razorpay over Stripe?</summary>

Stripe doesn't support Indian UPI and many Indian debit cards natively. ₹199 is a microtransaction — Razorpay handles UPI, NetBanking, Paytm, and all Indian wallets without additional setup. For an Indian student audience, this eliminates the single biggest payment drop-off point.

</details>

<details>
<summary>🎤 Why Web Speech API over Deepgram/AssemblyAI?</summary>

Web Speech API is built into Chrome and Edge — zero cost, zero latency to an external server, zero API key required. The tradeoff is browser-only (no mobile app). For the target audience (students on laptops practicing at home), this is the right call at this stage. Can be upgraded to Deepgram for mobile voice later.

</details>

## ⚡ Challenges Faced

<details>
<summary>🧩 Gemini returning malformed JSON</summary>

Gemini occasionally wraps JSON in markdown code fences or adds a preamble sentence. Solution: strip ` ```json ` markers before `JSON.parse()`, then wrap everything in `try/catch` with a fallback that shows generic feedback and logs the raw response for review.

</details>

<details>
<summary>🔄 JWT refresh flow across two deployments</summary>

Frontend on Vercel + backend on Render means cross-origin cookies. Required `SameSite=None; Secure` on the refresh token cookie, `credentials: 'include'` on Axios, and explicit CORS `origin` configuration. Took debugging to get right — now documented in the codebase.

</details>

<details>
<summary>🎤 Voice transcript timing with AI evaluation</summary>

Speech recognition is async and fire-and-forget. The challenge was knowing when the user *stopped* talking (silence detection) vs paused mid-sentence. Used a 2-second silence timeout on `SpeechRecognition.onresult` before treating the transcript as final and sending to Gemini.

</details>

<details>
<summary>📸 Score card PNG generation</summary>

`html-to-image` requires the element to be mounted in the DOM. Generating it server-side isn't possible. Solution: render the score card component off-screen (opacity: 0, position: absolute) after the session completes, call `toPng()`, then offer the download. The watermark for free users is added as a positioned overlay in the same component.

</details>

<details>
<summary>🏆 Leaderboard consistency</summary>

Multiple users completing sessions simultaneously could cause race conditions when calculating ranks. Solution: weekly scores are written per-session to the Leaderboard collection (not computed on read), and `node-cron` resets them every Sunday midnight. Rank is computed at read time via a MongoDB `$rank` aggregation pipeline.

</details>
